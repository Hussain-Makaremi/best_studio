## Guide: Prompt forms around clarity and state

A form is not just a stack of inputs. It is a decision path with labels, help text, validation, errors, confirmation, and recovery.

### Why form prompts need more detail

AI agents often generate forms that look acceptable but miss the states that make them usable: focus, validation, disabled, loading, helper text, and error recovery.

A form reference helps set input height, label weight, spacing, grouping, button placement, and the balance between clarity and density.

Use this page for: onboarding, checkout, signup, settings, profile editing, filters, and admin tools.

### Prompt forms with interaction states

1. **Define the form job** — Tell the agent whether the form collects, edits, filters, configures, verifies, or confirms information.
2. **Specify validation and recovery** — Ask for error messages, helper text, required fields, success states, disabled states, and loading behavior.
3. **Check mobile ergonomics** — Make sure labels, inputs, buttons, and error messages do not collide or shift awkwardly on small screens.

## Clarity — Labels should reduce thinking

The user should know what each field expects, why it matters, and what to do when something goes wrong.

A good prompt tells the agent to design the explanatory layer, not only the input boxes.

## Density — Form spacing depends on context

A signup form can be spacious. A settings form or admin filter panel may need tighter grouping.

Use references that match the context so the agent does not overinflate every control.

## Accessibility — Form polish includes accessibility

Focus states, contrast, target size, error association, and readable helper text are core parts of form design.

Ask for them explicitly when the agent builds production UI.
