# DESIGN.md Template

Template and guidance for creating DESIGN.md files — structured documents that capture design system decisions in a machine-readable format.

## Template

```markdown
# Design direction

Reference: [style URL and date reviewed]
Purpose: [audience and task]

## Typography
Display: [family, weight, size, line height, use]
Body: [family, weight, size, line height, reading width]

## Color roles
Canvas and surfaces: [values and where they apply]
Text and actions: [values and contrast requirements]

## Layout
Content width: [value or range]
Spacing rhythm: [repeated gaps, not every one-off measurement]

## Open decisions
[What the reference cannot tell you about your product]
```

## Typography as structure

Focus on the *role* of each typeface before recording dimensions. Distinguish between display, reading, labels, and code treatments.

> "A hero-sized headline is not a global heading token; explain where its scale ends" and denser content begins.

## Color with a job

Document canvas, surface, text, action, and state colors separately.

> "A hex code without its job cannot tell an agent when to use it, and a bright accent should not automatically spread to every control."

## Layout you can repeat

Capture recurring container widths, gaps, card treatment, and section transitions.

> "Distinguish repeatable layout rules from a single hero composition, then leave any unobserved responsive behavior open for your own design."
