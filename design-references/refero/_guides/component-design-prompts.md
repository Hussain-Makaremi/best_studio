# Component Design Prompts for AI Agents

Small component choices decide whether an AI-built interface feels coherent. Prompt components with visual references, states, and rules before generating the page.

Start with 24 curated references from 1,200+ matching styles.

## Prompt components like product UI, not decoration

A good component prompt defines behavior, states, density, hierarchy, and the visual system the component should belong to.

### Why component prompts need examples

Agents often design components independently, so buttons, cards, inputs, and tables end up feeling like they came from different products.

A real reference gives the agent a shared visual language for component weight, spacing, radius, labels, icons, and surface treatment.

Use this page when the screen structure is mostly right but the components still feel generic or inconsistent.

### Prompt components with states and system rules

1. **Name the component family** — Specify whether the agent is building forms, buttons, cards, tables, navigation, empty states, or a component set.
2. **Provide the reference system** — Paste the DESIGN.md and tell the agent which component qualities to preserve.
3. **Request all useful states** — Ask for hover, active, disabled, loading, empty, error, selected, and mobile states where relevant.

## States are part of the design

A component that only looks good in its default state is incomplete. Real product UI needs feedback and edge cases.

Prompt the agent to design those states from the beginning, especially for forms, tables, and navigation.

## Components should share one visual language

Radius, borders, shadows, icon size, label treatment, and spacing should feel related across the interface.

A reference helps the agent keep that relationship intact.

## Prompt one component problem at a time

Broad requests like "make the UI nicer" usually produce superficial changes.

Ask for a specific component family and a specific quality bar instead.
